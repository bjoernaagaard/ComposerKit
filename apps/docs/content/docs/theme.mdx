## Install

```bash
npx shadcn@latest add https://bjoernaagaard.github.io/ComposerKit/r/theme.json
```

The theme is a set of CSS variables. shadcn writes them into your global CSS file: light values on `:root`, dark colors on `.dark`. Every other item installs it for you.

The examples below also import the list of color roles. To run one exactly as the Code tab shows it, add that too:

```bash title="Add the sample data"
npx shadcn@latest add https://bjoernaagaard.github.io/ComposerKit/r/sample-data.json
```

This adds `content/` and `states/composer/fixtures.ts`.

## Anatomy

The theme has no components. It is three blocks of CSS variables:

```css title="Anatomy"
@theme inline {
  --color-primary: var(--primary); /* Tailwind classes such as bg-primary */
}

:root {
  --primary: #594fd7; /* light colors */
  --size-composer-control: 28px; /* sizes, spacing, type and motion */
}

.dark {
  --primary: #9095fd; /* dark colors */
}
```

Add the `dark` class to the root element to switch to the dark scheme. These docs do that with their theme switch.

## Keyboard

The theme has no controls of its own. It sets the color and width of the keyboard focus ring (`--ring`, `--border-focus-width`, `--border-focus-offset`), which every other item draws on keyboard focus. The rule for that ring:

## Accessibility

<SpecSection section="6. App shell > Light and dark" />

No WAI-ARIA Authoring Practices pattern covers a theme. Text and controls follow WCAG 2.2: [contrast (minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) and [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).
